# 工作区检查与改进 · 2026-10-29

## 整体判断

当前架构适合配置较低的办公本：C# 5 / 系统 .NET Framework，WinForms 负责窗口和事件，GDI+ 负责透明 PNG 分层，普通构建只用系统编译器。Node.js、Sharp、原始大图和 GIF 导出仅供离线开发，正式程序没有这些常驻依赖。当前 24 张运行 PNG 合计约 4 MB，嵌入单文件程序；切换角色或尺寸时按需解码，动作帧复用绘图表面。

核心流程是物理按键状态 → PetBrain / HandMotion → 按需调度 → SpriteRig 合成 → Win32 透明窗口。角色资料和手腕坐标由 assets/characters.json 生成，动画时长集中在 AnimationTiming.cs。这个方向值得保留，主要问题在刷新边界和素材分层质量。

## 本次已处理

1. **输入绕过刷新预算。** 原先每个有效键盘转换都会强制合成并提交窗口，独立动画定时器也在刷新。现在所有按键状态仍立即处理，输入画面和插值共用至少 33 ms 的提交间隔；一个间隔内合并到最新状态。首个可用帧可以立即显示，间隔内的短促动作可能合并显示。采用普通 WinForms 定时器，不提高系统计时精度。
2. **锁屏、挂起及断开会话的边界。** 现在锁屏、会话断开、系统挂起及主动隐藏都暂停绘图、清除按住状态、注销原始键盘输入并释放角色缓存与绘图表面。锁屏、会话断开、系统挂起分别记录，重连不会误清除锁屏暂停状态。恢复后保留手动睡姿。专注计时按经过时间继续计算，暂停显示期间最多每分钟检查一次，恢复时立即校正。
3. **完全静止后的唤醒。** 睡姿稳定且没有专注计时时彻底停止定时器，替代原先每分钟唤醒一次。点击表情的保持段直接等到淡出时刻，避免每 30 ms 检查相同画面。
4. **真由理袖口和双手。** [原作官方立绘](https://steinsgate.jp/darling/common/img/cc2.png)显示的是短泡泡袖，露出前臂正常。旧图在手腕处又多出独立蓝色喇叭袖，造成“袖子断开”的观感。此次重画待机前臂和睡姿叠手，去掉多余袖口；待机保留原头部与上身像素，睡姿让两只手可以分别追溯到自己的前臂。提示词和参考关系保存在 artwork/mayuri-revision-prompts.md。
5. **活动手部的碎线。** 离线工具在已完成皮肤连通分割后又按颜色过滤一次，漏掉部分浅色高光和抗锯齿描边，这些像素留在固定身体层中，手一动便出现碎线。去掉重复过滤，并重导出角色手层；静止姿势仍从完整原图直接绘制。
6. **预览误导。** 动作概览原来用睡眠第 0 帧，实际展示闭眼待机。现在展示最终睡姿，并增加真由理四档实际尺寸检查图。

## 性能与验证

原始基线保存在 artifacts/verification/before/；最终报告保存在 artifacts/verification/current/。测试使用当前开发电脑、默认小号、真实透明窗口和合成输入，不能当成办公本上的硬性 CPU 或内存保证。

| 场景 | 原始基线 | 最终验证 |
| --- | --- | --- |
| 普通合成打字，10 秒 | 59.9 次提交/秒，单核 7.63% | 20.8 次提交/秒，单核 3.58%，工作集 39.1 MB |
| 密集输入，10 秒 | 未设统一上限 | 19,968 次有效转换，21.5 次提交/秒，单核 3.90% |
| 待机，15 秒 | 2 次重绘 | 2 次重绘 |
| 600 次窗口绘图后 GDI 句柄 | 38 → 38 | 38 → 38 |

最终精确数字以 current/ 中的 motion.txt、burst.txt 和 self-test.txt 为准。CPU 百分比按单核计算；多核任务管理器的总占比会更小。旧待机测试每 20 ms 用 DoEvents 轮询，混入了测试器自身的开销；此次改为普通消息循环，因此不把新旧待机 CPU 数字直接比较。

执行 scripts/validate-assets.ps1、scripts/test.ps1 -Performance，最终通过 95 项检查，并导出静态图、逐帧图和 GIF 检查。测试覆盖按键自动重复、独立双手、快速输入状态完整性、刷新上限、最后松开收敛、衣物固定、表情与打字并行、透明边缘、休眠停表、会话暂停组合与 GDI 句柄稳定性。GIF 只供离线审阅，仍是 50 fps 的动作采样，不能据此推断正式窗口的提交频率。

本次没有以真实鼠标、物理键盘、Win+D、实际锁屏/合盖或桌面录屏进行人工验收；会话切换与挂起通过同一暂停处理入口验证。旧机上的实际耗电、丢帧和硬件到显示的延迟仍须实机确认。

## 后续值得做的事

- **动作质感：** 当前手部是小角度旋转和轻微拉伸，放大看局部轮廓仍有轻微重叠与锯齿。若希望手指更像实际敲击，可以离线画少量手指接触姿势，运行时仍只在输入和回弹期间切换。收益主要是美术真实感，保持衣袖与躯干固定即可，无需增加常驻动画。
- **入睡过渡：** 当前是两张不同姿态之间 360 ms 的预乘透明度混合，中途仍可能看见短暂双轮廓。可离线增加两三张衔接姿态改善下沉感，睡稳后继续停刷。它比增加持续呼吸、摆动更符合低负荷陪伴用途。
- **不同 DPI 的外接显示器：** 当前使用系统级 DPI 感知；若办公本经常在不同缩放比例的屏幕间拖动，可再补每屏 DPI 适配并在真实双屏检查，避免 Windows 二次缩放模糊。
- **扩展后的缓存：** 现在只有四个角色，按需缓存体量较小，隐藏时会释放。若以后加入大量角色，可改成仅保留最近一两个角色的缓存；此时再引入淘汰策略更有实际收益。

本次保留现有四个角色的整体画风、稳定待机和轻量运行框架。后续优先改善短暂动作的可读性与衔接，再决定是否增加新动作。
